**Non-destructive qualification helpers implemented / unmerged.** Added a test-only cache-aware storage model driven by the actual consuming publisher orchestration. `verify_package` returns immutable owned bytes only after every file matches. Later source overwrite, deletion or replacement cannot alter that result. Missing or unexpected files fail the whole operation. Candidate creation and verification neither persist nor replace accepted records. A plugin-local checksum file has no special authority. The future loader must consume verified bytes rather than reopen paths.

The directory reader rejects root/descendant symlinks, Windows reparse points, special files, invalid UTF-8 names and nonportable paths. Capability-based no-follow opens and opened-handle checks protect against replacement after classification. Unix opens are nonblocking before type validation so a FIFO swap cannot block the reader. The host supplies trusted root ancestors. Collection is not an atomic filesystem snapshot; every returned buffer still has to match the trusted record. Empty directories are checked and bounded but not hashed.

Default limits bound file count, depth, path length, directory work and actual bytes read: 2,048 files, 16 MiB per file and 64 MiB total. Work is synchronous and must be scheduled appropriately by the eventual installer. The implementation uses `sha2` 0.10.9, capability filesystem crates locked to 3.4.6, and `tempfile` for tests. The module remains private with no new Tauri commands or loading path.

#### Manifest schema decisions

The owner approved the version-1 schema now implemented by the pure module described above. The [field rules](package-api-proposal.md#manifest-field-rules) and [internal guide](manifest-resolution.md) describe current enforcement. The decisions preserve these boundaries:

- Require integer `manifest_version = 1`, strict types and known fields throughout. Defaults apply only to absent fields. Package SemVer is separate from the manifest format version.
- Derive canonical package identities from optional namespace and stable machine name. Machine identifiers use lowercase ASCII letter/digit groups with single hyphens and a 256-byte per-field maximum. Display text supports any language, with 1 KiB display-name and 4 KiB description limits.
- Require 1–32 components with explicit frontend kind, entry, profile, scope, capabilities and display metadata. Unknown kinds reject the whole manifest; unknown profiles remain valid declarations but block static eligibility. Installation disclosures and runtime import gates are not implemented.
- Require exact verified entry/style membership and portable paths. Styles default to empty, with at most 16 entries. The parser does not import JavaScript, inspect activation exports or load styles.
- Reject duplicate component IDs, dependency aliases and target package/component/binding tuples. Reject self-dependencies. API lists require unique ID/major pairs and support multiple explicit majors. Resolution requires every requested pair, with no automatic major negotiation.
- Limit dependencies to 64 per component, provided APIs/commands to 32 per component and requested APIs/commands to 32 per dependency. API/command IDs, contract IDs and command aliases use exact non-whitespace strings with 256 UTF-8-byte limits. Runtime publication/lookup checks remain separate.
- Accept only approved capability values and permission operation/resource pairs. Duplicate permission pairs within a list are errors; the same pair at package and component levels becomes one effective declaration. Application components cannot inherit project-file requirements. None of this issues grants.
- Allow omitted package-version requirements and lifecycle-only dependencies. Exact SemVer or conjoined comparisons apply only to installed candidates. Optional lists default to empty. Resolution downloads nothing and selects no package version.
- Bound supplied manifest bytes to 64 KiB before decoding/parsing. Future acquisition must enforce bounded reads separately. Other package/extraction and aggregate catalog budgets remain host work.
